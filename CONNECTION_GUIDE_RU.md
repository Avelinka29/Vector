# VECTOR: подробная инструкция подключения iPhone к серверу на Mac

Проверено по настройкам проекта 9 ноября 2026. Инструкция для локального запуска через Docker на твоём Mac. Все команды ниже выполняются в Терминале Mac, если явно не написано другое.

## Как устроено подключение

Приложение VECTOR на iPhone обращается к серверу на Mac. Сервер запущен в Docker и использует базу PostgreSQL. Для работы нужны включённый Mac, запущенный Docker, работающий сервер и связь телефона с Mac по сети.

Установка приложения через USB сама по себе не настраивает сетевой доступ к серверу. В этой инструкции связь с сервером проверяем через Wi-Fi или точку доступа.

Сейчас в проекте указан адрес:

```text
http://MacBook-Air-YULIYA.local:8002
```

Он использует локальное имя Mac. Оно может продолжать работать после смены IP, но не во всех сетях разрешаются имена `.local`. Если имя не работает, проверяем числовой IP.

Запомни различия:

- `8002` — порт VECTOR, который используют Mac и iPhone.
- `8000` — внутренний порт контейнера. В приложении его не указываем.
- `/health` — проверка, отвечает ли сервер. Она не проверяет все функции приложения и доставку писем.
- `localhost` и `127.0.0.1` — устройство, на котором открыт адрес. На Mac это Mac, на iPhone — iPhone.
- IP из инструкции, например `172.20.10.2`, — пример. Твой адрес может быть другим.

**Главное правило: идём по порядку — Docker → сервер на Mac → связь iPhone → адрес в приложении.**

## Шаг 1. Подготовь Mac и iPhone

1. Включи Mac, войди в свою учётную запись.
2. На время проверки подключи Mac к питанию и оставь крышку открытой.
3. Выбери один из двух вариантов подключения ниже.

### Вариант А: общий Wi-Fi

1. На iPhone открой «Настройки» → «Wi-Fi».
2. Посмотри название сети с галочкой.
3. На Mac нажми значок Wi-Fi в строке меню или открой «Системные настройки» → «Wi-Fi».
4. Подключи Mac к той же сети.
5. Если есть обычная и гостевая сеть, используй обычную. В гостевой сети устройства часто не могут обращаться друг к другу.

### Вариант Б: Mac подключён к точке доступа iPhone

1. На iPhone открой «Настройки» → «Режим модема». В зависимости от версии iOS пункт может находиться в «Сотовая связь».
2. Включи «Разрешать другим».
3. Посмотри пароль Wi-Fi на этом экране.
4. На Mac открой список Wi-Fi сетей.
5. Выбери сеть своего iPhone и введи пароль, если его запросят.
6. Убедись, что Mac действительно подключён к iPhone, а не остался в домашней сети.
7. Теперь IP Mac нужно узнавать заново. Старый домашний адрес может уже не работать.

Пока оставь VPN включённым, если он нужен для работы. Проверка доступа к локальной сети через настройки VPN описана в шаге 8.

## Шаг 2. Запусти Docker

1. Нажми на Mac `⌘Пробел` — откроется Spotlight.
2. Найди приложение, через которое у тебя запускается Docker.
3. Если используешь Docker Desktop, введи `Docker` и открой его. Если контейнеры запускаются другим приложением, открой именно его; устанавливать второй Docker не требуется.
4. Дождись, пока приложение закончит запуск. Открытое окно ещё не всегда означает, что Docker уже готов.
5. Снова нажми `⌘Пробел`, введи `Терминал` или `Terminal` и открой его.
6. Вставь команду и нажми Enter:

```bash
docker info
```

**Если получилось:** появятся сведения о Docker, включая раздел Server. Можно переходить к шагу 3. Эти сведения не нужно никуда копировать целиком.

**Если `Cannot connect to the Docker daemon`:** Docker ещё не запущен или выбран недоступный Docker engine. Дождись запуска своего приложения Docker и повтори команду. Если оно уже работает, посмотри:

```bash
docker context ls
```

Звёздочка показывает выбранное окружение. Не переключай его наугад: другое окружение может не содержать твою базу VECTOR. Если причина неясна, сохрани текст ошибки и этот список для диагностики.

**Если `command not found: docker`:** Терминал не видит команду Docker. Проверь запуск и установку своего Docker-приложения. IP в Xcode пока менять бессмысленно.

**Если `No such file or directory`:** папка проекта была перемещена или путь введён не полностью. Найди папку проекта в Finder, внутри неё — `backend`. В Терминале набери `cd ` с пробелом, перетащи папку `backend` из Finder в окно Терминала и нажми Enter. Затем снова проверь `pwd`.

## Шаг 4. Запусти контейнеры VECTOR

В Терминале из папки `backend` выполни:

```bash
docker compose up -d
```

Дождись завершения команды. Для обычного запуска уже собранного проекта этого достаточно. `-d` означает, что сервер продолжит работать в фоне после завершения команды.

Затем выполни:

```bash
docker compose ps -a
```

Найди сервисы:

- `api` — сервер приложения;
- `postgres` — база данных;
- `adminer` — интерфейс просмотра базы, для самого входа в приложение он не нужен.

У `api` ожидается статус `Up` и опубликованный порт наподобие `0.0.0.0:8002->8000/tcp`. У `postgres` — `Up`, обычно с `healthy`. После старта база может некоторое время показывать `starting`.

**Если `api` имеет статус `Exited` или постоянно перезапускается:** выполни:

```bash
docker compose logs --tail=80 api
```

**Если проблема с `postgres`:** выполни:

```bash
docker compose logs --tail=80 postgres
```

Сохрани текст ошибки. Смена IP не исправит падение сервера или базы.

**Если написано `port is already allocated` / `address already in use`:** порт занят другой программой или контейнером. Для просмотра контейнеров выполни:

```bash
docker ps --format 'table {{.Names}}\t{{.Ports}}'
```

Найди, кто использует `8002`. Не останавливай незнакомый контейнер наугад; сначала установи, какому проекту он принадлежит. В VECTOR порт `8002` уже согласован с приложением.

**Если написано, что external volume `backend_vector_postgres_data` не найден:** остановись и проверь Docker-окружение. Проект использует существующее хранилище базы. Создание пустого хранилища не восстановит прежние аккаунты и данные.

## Шаг 5. Проверь сервер на самом Mac

Выполни:

```bash
curl --max-time 5 http://localhost:8002/health
```

Успешный ответ:

```json
{"status":"ok"}
```

Пробелы в JSON могут отличаться — это нормально.

Можно проверить и через Safari **на Mac**, вставив в адресную строку:

```text
http://localhost:8002/health
```

Если сервер только запустился, подожди примерно 10 секунд и повтори проверку.

**Если `Failed to connect` / `Connection refused`:** на этом адресе и порту нет доступного сервера. Вернись к шагу 4 и проверь `api` и его логи.

**Если `Operation timed out`:** ответ не пришёл за 5 секунд. Проверь контейнеры и логи; один тайм-аут не доказывает, что виноват VPN.

**Если открывается другая страница или ответ 404:** проверь, что указан именно `http://localhost:8002/health`, и что порт 8002 принадлежит VECTOR.

**Не переходи к редактированию IP в Xcode, пока эта проверка не работает.**

## Шаг 6. Узнай текущий IP Mac

IP нужно смотреть после подключения к той сети, в которой будешь запускать приложение.

### Через настройки Mac

1. Нажми меню Apple `` в левом верхнем углу.
2. Открой «Системные настройки».
3. Открой «Wi-Fi».
4. У подключённой сети нажми «Подробнее» / Details.
5. Найди раздел «TCP/IP».
6. Найди поле «IP-адрес» / IPv4 Address.
7. Запиши его точно, вместе с точками.

Не путай IP Mac с полем «Маршрутизатор»: последнее — адрес роутера или телефона, раздающего интернет. Не используй адрес контейнера Docker или публичный IP с сайта «мой IP».

### Через Терминал

Выполни:

```bash
ipconfig getifaddr en0
```

Если увидишь, например:

```text
172.20.10.2
```

это кандидат на адрес Mac в Wi-Fi сети. Сверь его с подключением в настройках.

Если команда ничего не показала, Wi-Fi может использовать другой интерфейс. Для просмотра соответствий выполни:

```bash
networksetup -listallhardwareports
```

Найди блок `Hardware Port: Wi-Fi`, а в нём `Device`, например `en1`. Тогда выполни:

```bash
ipconfig getifaddr en1
```

Подставляй имя из своего вывода. Интерфейсы `utun…` обычно связаны с VPN; их адрес для этого сценария не нужен.

Если видишь адрес, начинающийся на `169.254`, проверь настройки подключения: это часто означает, что Mac не получил обычный адрес от сети. Переподключись к Wi-Fi и снова проверь IP.

## Шаг 7. Проверь этот IP на Mac, затем на iPhone

Во всех примерах ниже замени `172.20.10.2` на свой IP из шага 6.

### Сначала на Mac

Выполни:

```bash
curl --max-time 5 http://172.20.10.2:8002/health
```

Нужен ответ `{"status":"ok"}`.

Если `localhost` работает, а IP на Mac — нет, ещё раз проверь текущий IP, сеть и публикацию порта `8002` в `docker compose ps`. Затем проверь firewall и VPN по шагу 8.

### Теперь на iPhone

1. Открой Safari.
2. Нажми адресную строку.
3. Удали старый адрес целиком.
4. Введи полный адрес с `http://`, своим IP, портом и `/health`:

```text
http://172.20.10.2:8002/health
```

5. Нажми «Перейти».
6. Ожидается страница с `{"status":"ok"}`.

Здесь используется **http**, не https: в текущей локальной конфигурации HTTPS на порту 8002 не настроен.

**Если на iPhone ответ есть:** сеть и адрес доступны. Переходи к шагу 9.

**Если на Mac ответ есть, а на iPhone нет:** сначала выполни шаг 8. Пересборка приложения пока не исправит связь между устройствами.

Дополнительно можно открыть на iPhone:

```text
http://MacBook-Air-YULIYA.local:8002/health
```

Если числовой IP работает, а имя `.local` — нет, используй числовой IP в приложении. Это не требует изменений Google или Gmail.

## Шаг 8. Если iPhone не видит Mac

Проверяй пункты последовательно. После каждого изменения снова открывай тот же `/health` в Safari на iPhone.

### 8.1. Сеть

- Убедись, что Mac не переключился на другую Wi-Fi сеть.
- При общем Wi-Fi убедись, что iPhone остаётся подключён к нему.
- При режиме модема проверь, что Mac подключён именно к этому iPhone.
- Повтори получение IP: после переподключения он мог измениться.
- В гостевой, учебной или общественной сети может работать изоляция устройств. Попробуй личную точку доступа и получи новый IP Mac. Одинаковое имя Wi-Fi само по себе не гарантирует связь между устройствами.

### 8.2. VPN

Открой настройки VPN-приложения на Mac и на iPhone, если VPN включён на обоих устройствах. Найди параметр с названием вроде:

- Allow LAN;
- Allow local network;
- Local network access;
- «Разрешить локальную сеть»;
- Split tunneling / «Раздельное туннелирование».

Если есть отдельное разрешение LAN, включи его. Если доступно только раздельное туннелирование, настрой исключение для локальной сети по инструкции именно твоего VPN. Названия и возможности у разных VPN отличаются; единой кнопки нет.

Не требуется отключать VPN целиком. Не добавляй случайные маршруты и адреса исключений: локальная сеть должна соответствовать текущему подключению Mac.

### 8.3. Брандмауэр Mac

1. Открой `` → «Системные настройки» → «Сеть» → «Брандмауэр».
2. Если название или расположение отличается, найди «Брандмауэр» поиском в системных настройках.
3. Если он включён, открой «Параметры» / Options.
4. Проверь, не включён ли режим «Блокировать все входящие подключения».
5. Проверь разрешения приложения Docker или используемого контейнерного движка. Для него не должно быть запрета входящих соединений.
6. Если macOS показывает запрос разрешить входящие подключения Docker, разреши их для используемого Docker-приложения.
7. Сохрани изменения и повтори `/health` с iPhone.

Не нужно отключать весь брандмауэр навсегда. Конкретный процесс, публикующий порт, зависит от Docker-приложения. Если его нет в списке и блокировка неясна, сохрани скриншот настроек для диагностики. [Инструкция Apple по брандмауэру](https://support.apple.com/en-gb/guide/mac-help/mh34041/mac).

### 8.4. Сон Mac

Mac должен оставаться включённым и бодрствующим. Если проблема появляется после закрытия крышки или долгого простоя, открой крышку, разбуди Mac и снова проверь сервер.

На время демонстрации можно открыть отдельное окно Терминала и выполнить:

```bash
caffeinate -i
```

Оставь это окно открытым. Команда временно препятствует автоматическому сну при бездействии; она не гарантирует работу при закрытой крышке. Когда демонстрация закончится, нажми в этом окне `Control+C`.

## Шаг 9. Поменяй адрес в Xcode

Делай это после успешного открытия `/health` на iPhone. Если нынешний адрес `.local` уже работает, менять его необязательно.

### Найди правильный файл

Нужен именно этот файл:

```text
/Users/avelinamaksimchik/Desktop/projects/Vector/program/Vector/Vector/Info.plist
```

1. Открой проект VECTOR в Xcode.
2. Нажми `⌘1`, чтобы открыть список файлов слева.
3. В основной папке `Vector` найди файл `Info` или `Info.plist`.
4. Не выбирай копию из `New Group` и не открывай `GoogleService-Info.plist`: это другой файл.
5. Если не можешь найти, открой Finder, нажми `⌘⇧G` и вставь путь к папке:

```text
/Users/avelinamaksimchik/Desktop/projects/Vector/program/Vector/Vector
```

6. Найди там `Info.plist` и открой его в Xcode через «Открыть в программе».

### Измени одно значение

1. В открытом файле найди строку `VECTOR_API_BASE_URL`.
2. В столбце Value / «Значение» сейчас указано:

```text
http://MacBook-Air-YULIYA.local:8002
```

3. Дважды нажми на значение.
4. Введи адрес, который успешно открывался на iPhone, но **без `/health`**. Пример:

```text
http://172.20.10.2:8002
```

5. Нажми Enter, затем `⌘S`.

Если файл открыт как XML, измени только строку `<string>` сразу после нужного ключа:

```xml
<key>VECTOR_API_BASE_URL</key>
<string>http://172.20.10.2:8002</string>
```

Снова: `172.20.10.2` — пример, подставь свой рабочий IP. В значении не должно быть пробелов, `/health` или `/api/v1`.

При смене локального IP не требуется менять:

- `GIDClientID` и Google URL schemes;
- настройки в Google Cloud;
- Gmail OAuth и пароль почты;
- `backend/.env`;
- порты в `docker-compose.yml`;
- `.pbxproj`.

## Шаг 10. Установи приложение с новым адресом

Адрес берётся из установленной сборки. Сохранение Info.plist на Mac само по себе не обновляет приложение на iPhone.

1. Подключи iPhone к Mac кабелем, если так обычно запускаешь приложение.
2. Разблокируй iPhone и подтверди доверие компьютеру, если появится запрос.
3. В Xcode в верхней панели выбери схему VECTOR и свой физический iPhone, а не симулятор.
4. Нажми квадратную кнопку Stop, если приложение ещё запущено из Xcode.
5. Нажми Run — треугольник, или `⌘R`.
6. Дождись успешной сборки и установки на телефон.
7. Если сборка завершилась ошибкой, новая версия не установлена. Сохрани текст первой ошибки — старое приложение может всё ещё содержать прежний адрес.
8. В запустившемся приложении разреши доступ к локальной сети, если появится запрос.
9. Повтори действие, которое раньше не работало: вход или загрузку данных.

Удалять приложение для обычной смены IP не нужно: в нём могут храниться локальные данные и фотографии документов.

## Шаг 11. Если Safari видит сервер, а VECTOR всё ещё не работает

1. Проверь, что в Info.plist стоит точно тот адрес и порт, которые работали в Safari, но без `/health`.
2. Проверь, что изменение сделано в основной папке Vector, а не в копии.
3. Убедись, что Xcode успешно установил приложение именно на твой iPhone.
4. На iPhone открой «Настройки» → «Конфиденциальность и безопасность» → «Локальная сеть».
5. Если VECTOR есть в списке, включи ему доступ.
6. Закрой и открой VECTOR после изменения разрешения. Если его нет в списке, снова вызови сетевой запрос в приложении; если запроса разрешения нет, зафиксируй это для проверки конфигурации приложения. Не сбрасывай все настройки телефона.
7. Посмотри точный текст ошибки.

«Неверный пароль», «Недействительный токен Google», «Аккаунт заблокирован» и ошибка отправки письма — отдельные проблемы авторизации или сервиса. Если такой ответ пришёл от сервера, смена IP не исправляет его причину.

Для симулятора на том же Mac допустим `http://127.0.0.1:8002`. Для физического iPhone используй адрес Mac в сети.

## Шаг 12. Когда нужно пересобрать сервер

Если изменился только IP Mac, Docker пересобирать не требуется: обнови адрес приложения и установи его через Xcode.

Если изменён код backend, настройки Google или `backend/.env`, выполни:

```bash
cd /Users/avelinamaksimchik/Desktop/projects/Vector/program/Vector/backend
docker compose up -d --build api
```

Дождись завершения, затем проверь:

```bash
curl --max-time 5 http://localhost:8002/health
```

Обычный `docker compose restart` не подхватывает новые переменные окружения. `up` пересоздаёт сервис при изменении конфигурации, а `--build` собирает код. [Документация Docker Compose](https://docs.docker.com/reference/cli/docker/compose/up).

Не используй удаление volumes, сброс Docker или удаление базы как способ починить IP. Для этих проверок они не нужны.

## Если не получилось: что сохранить для диагностики

Сообщи, на каком шаге перестало получаться, и приложи:

1. Какая сеть используется: общий Wi-Fi или точка доступа iPhone.
2. Текущий локальный IP Mac.
3. Значение только `VECTOR_API_BASE_URL`.
4. Открывается ли `/health` через localhost на Mac.
5. Открывается ли `/health` через числовой IP на Mac.
6. Открывается ли тот же адрес в Safari на iPhone.
7. Вывод `docker compose ps -a`.
8. Точный текст ошибки в приложении; при падении сервера — нужные строки из `docker compose logs --tail=80 api`.

Не присылай содержимое `.env`, OAuth JSON, пароли и токены. Перед отправкой логов проверь, нет ли там ссылок сброса пароля или других секретов.

## Короткий порядок действий при следующем запуске

1. Включить Mac и Docker.
2. Подключить Mac и iPhone к выбранной сети.
3. Открыть Терминал и перейти в папку backend.
4. Выполнить `docker compose up -d`.
5. Проверить `http://localhost:8002/health` на Mac.
6. Проверить текущий адрес Mac с iPhone через Safari.
7. Если адрес изменился — обновить `VECTOR_API_BASE_URL` в основной Info.plist.
8. Установить новую сборку через `⌘R`.
9. Оставить Mac включённым и Docker работающим.

Если телефон находится в другой сети, обычный локальный IP Mac не будет доступен напрямую. Эта инструкция рассчитана на локальное подключение; проброс портов на роутере для него не нужен.
